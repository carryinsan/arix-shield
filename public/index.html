Security at the application layer

Protection where your business logic lives.

Run the local SDK before your API routes. Use the hosted service for keys, policy, distributed state and telemetry—without making every customer request traverse a separate proxy.

01

Request inspection

Bounded lexical checks for SQL injection, XSS, SSRF, path traversal, NoSQL operators, command injection and prompt-injection indicators.

02

Distributed quotas

Atomic token-bucket, sliding-window, fixed-window and leaky-bucket algorithms backed by Upstash Redis Lua scripts.

03

DPoP browser telemetry

Non-exportable P-256 browser keys sign short-lived visit proofs. The publishable project identifier does not grant backend access.

04

Active deception

Known canary-key or invalid proof use can be routed to deterministic synthetic data and recorded as a trap event.

05

Leak attribution

Signed zero-width watermark markers map leaked snippets to server-side session, user, IP hint and timestamp records.

06

Useful telemetry

Visitor heartbeats, threat history, request counters and enforcement policies in a responsive developer dashboard.

Deployment model

Keep the enforcement path close to your code.

ArixShield is not a network-layer DDoS scrubbing network. Your app runs local validation and authorization; ArixShield Cloud stores project controls and security signals.

A

Your application

SDK middleware inspects bounded request context and applies local limits before sensitive handlers execute.

B

ArixShield API

Vercel Node functions handle account sessions, DPoP visitor proofs, canary events, policy and forensic decoding.

C

Upstash Redis

Atomic Lua quotas, session records, project state, watermark attribution and bounded event rings.
